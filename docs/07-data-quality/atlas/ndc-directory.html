NDC Directory: from a package code to a product

An NDC (National Drug Code) is the code printed on every US drug package. The NDC Directory is FDA's list of them. We need it for one job: a recall names a package; the directory tells us which product (application number) and which ingredient that package is. Every number below was measured by prototypes/explore/recalls_ndc_atlas.py on FDA's files of 2026-10-20 and openFDA's copy of 2026-10-16.

Overview

Four lists, not one

FDA splits the directory into four files. A recalled package can sit in any of them. The main file alone found 89 of the 193 recall rows the directory could place; the other three found the rest.

What's messy (measured)
  • Not clean text. 342 lines of product.txt, 694 of the excluded file and 97 of unfinished are not valid UTF-8. A default read fails. Latin-1 reads them all.
  • The excluded file is stripped. Ingredient, generic name and dosage form are blank on 100% of its 206,937 products. Only brand name, labeler and application number stay. Our flags there: discontinued by the firm (D) 1,803, inactivated by FDA (I) 602, listing expired (U) 3.
  • Compounded products live apart. 0 of the 287 compounder package codes for our 13 appear in the main file. RxNorm gives an RxCUI for 147 of them, all as ALIEN; 140 are UNKNOWN. They have no application number.
  • The same package repeats. The compounder list has 720 rows for our 13 but only 287 distinct packages (224 products, 33 firms). Each half-year report (2024-2 to 2026-1) lists them again.
  • Bulk GLP-1 powder is common. 119 semaglutide and 114 tirzepatide products in the unfinished file. 105 of all our bulk products are labelled "for human prescription compounding". This is the supply behind the compounded recalls, not something a hospital dispenses.
  • Combinations. 483 of 1,344 listed products have 2+ ingredients: hydrocodone + acetaminophen 202, oxycodone + acetaminophen 128, buprenorphine + naloxone 96.
  • Codes get reused. Recall D-0153-2017 printed 0409-4093-32 for Hospira fentanyl. Today that code belongs to a chromium product.
  • Three 10-digit shapes (4-4-2, 5-3-2, 5-4-1). Billing systems use an 11-digit form (5-4-2) with a zero added. We compare everything as 11 digits.

How it joins to the others

The chain
recall NDC ──▶ package (11-digit) ──▶ product ──▶ APPLICATIONNUMBER ──▶ Product object ──▶ label (Drugs@FDA / DailyMed)
                                         │                 ▲
                                         └─▶ SUBSTANCENAME │ FAERS nda_num lands here too
                                                ──▶ RxNorm ingredient ──▶ Drug object

The application number is the key that ties recalls, FAERS (nda_num) and labels to the same Product (D027). It is filled on 98.9% of our listed products; the 15 blanks are all "unapproved drug other".

For approved products, RxNorm and the directory agree almost fully. The gap is entirely compounded and bulk products.

openFDA's JSON copy, our 1,344 finished products

The JSON adds an openfda block: RxCUI filled on 95.5%, label set ID (spl_set_id) on 95.8%, empty on 56 products. That set ID is a direct link to the DailyMed label. The FDA text files do not carry it.

Recalls placed by the directory (527 recall rows with an NDC)

193 placed (37%): listed 89, excluded 75, 503B list 24, unfinished 5. Of these, 183 name the same ingredient as the recall text. The 10 that don't are mostly brand-only names in the excluded file (examples: Norco, Endocet, Oxecta), plus the reused chromium code. 150 carry an application number.

Decision to propose
  • Build one ndc_reference table from all four files: 11-digit NDC, the code as printed, product NDC, application number, ingredients, labeler, list (listed / excluded D·I·U·E / 503B / unfinished), start and end dates.
  • Use it as the Package → Product bridge for recalls. Use RxNorm for Product → Drug. For the label, prefer the application number (D027); use openFDA's spl_set_id only as a cross-check.

A product ID includes the label version, so a label update shows up as one ID gone and one new. Counted by product code instead, only 91 codes are new and 208 are gone in those 4 days. The rest are new label versions of existing products.

Decision to propose
  • Load weekly, together with recalls. A daily load buys nothing for the officer: about one change a day for our 13, and none of it is a safety event.
  • Keep each weekly snapshot, so a recall code can be resolved as of the recall date (the chromium case). Directory changes are not ChangeEvents on her screen.
6

Decision

To propose
  • Add the NDC Directory as a reference source (four FDA files, weekly). Its job is identity only: Package → Product → application number.
  • Compounded products are Products too. Key = labeler + product code, category "503B compounded", no application number, tagged compounded. They link to a Drug through the ingredient name, since RxNorm mostly doesn't know them.
  • Excluded listings stay. They are where old recalls point. Mark them "no longer marketed" rather than drop them.
  • Unfinished (bulk) products stay in the reference table for recall lookups but never appear as products on her screen.

Safety officer lens (persona view, not a real interview). She thinks in what is on her shelf: brand, strength, pack. The directory is how a recall line "NDC 71170-811-02" becomes "Apollo Care semaglutide 2.25 mg vial, compounded, not FDA-approved". That sentence is what makes the recall card trustworthy, and it must show where it came from: "from the FDA 503B list, report 2026-1".
