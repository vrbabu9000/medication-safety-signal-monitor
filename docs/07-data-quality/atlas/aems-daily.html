Can a Foundry pipeline pull it daily?

Legally yes for the files, reliably no for the dashboard

Quarterly files yes

Public, stable URL pattern, documented layout. Foundry can poll the page weekly and pick up 2026 Q3 when it lands. Based on the last 4 postings, that should be around late October (estimate). This is already our plan (D029).

Daily dashboard no

No documented endpoint. The data sits behind a disclaimer click inside an interactive dashboard app. Automating that means scraping or calling undocumented endpoints. That breaks our rules, and it breaks the pipeline whenever FDA changes the dashboard.

Decision

Recommend (b): one manual export for the demo, plus a roadmap item

Proposed
  • Pilot: FAERS stays quarterly (D029 holds). The "since last review" view runs on quarterly deltas.
  • Demo (optional, about 30 minutes, you): open the dashboard, accept the disclaimer, filter to semaglutide and the latest day, export the case listing to Excel, and upload it to Foundry as faers_dashboard_manual_snapshot, stamped with the export time. Show it as "new reports since the last quarterly file, not yet in the signal math".
  • Roadmap: "Daily FAERS when FDA documents an AEMS API." Add a monthly check of FDA's AEMS page to the monitoring list.
  • Why not (a), a daily feed as a stretch goal: there is nothing official to build against. A stretch goal that relies on scraping would fail the compliance review.

What we could not check

Unverified
  • Row cap and exact columns of the dashboard Excel export. FDA says only "limited". Check during the manual export.
  • Whether the export carries primaryid / caseversion. Without them, the snapshot cannot be deduplicated against the quarterly files. It can only be shown, not counted.
  • Whether FDA ever shipped the promised AEMS API. Trade press only; no FDA page found.
  • The exact 2026 Q3 posting date (estimated from past postings).
