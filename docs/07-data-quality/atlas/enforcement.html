FDA recalls: which of our 13 drugs have an active recall?

Get it

What it is

FDA publishes the Enforcement Report every Wednesday. openFDA (FDA's public API) serves the same rows as an API and as one bulk file. The bulk file holds every drug recall since 2012. It is small: 4.0 MB zipped, 28 MB unzipped. So the pipeline can reload all of it every week.

How we pick "our" recalls

The drug is named only in free text (product_description). We match the 13 ingredient names as whole words, ignoring case. That keeps apomorphine out of morphine (2 apomorphine recalls excluded). Tall-man spellings such as "fentaNYL" and "HYDROmorphone" still match. Adding brand names (Percocet, Norco, Ozempic…) found only 1 extra recall (a Percocet row). So ingredient words are enough.

What's messy (measured)
  • The newest report in the bulk file is 2026-10-07. Today is 2026-10-20. The data is 13 days old, and the 2026-10-14 report is not in it yet.
  • A recall reaches the report a median 42 days after the firm started it (recall_initiation_date → report_date).
Decision to propose
  • Load the bulk file once a week (Thursday). Keep each weekly file as a raw snapshot. Show the "as of" date on screen (D028).
  • Select our recalls by whole-word ingredient match on product_description. Brands are not needed.

What's messy (measured)
  • The openfda block is nearly empty. Filled on 74 of 890 rows (8.3%) and 18 of 116 Ongoing. For all drugs it is 17.4%. We cannot rely on FDA's own enrichment.
  • Only 59% carry an NDC. 527 of 890 rows have an NDC in the text. 2015 is the worst year (14 of 158): PharMEDium used its own "Product code 2T6165" instead. Since 2021 most years are above 70%, but 2025 drops to 24 of 52.
  • Five NDC shapes. 5-3-2 (313), 5-4-2 (158), 4-4-2 (91), 5-4-1 (63) and 10 written without dashes. 4 of those are 10 digits with no dashes, which can be split 3 ways. 63 rows list 2 or more NDCs (one per pack size).
  • Most of it is compounded. 557 of 890 rows (63%) are from compounders: 527 say so in the text, 82 have an NDC whose labeler is on FDA's 503B list, 52 both. Of the 116 Ongoing, 64 are compounded.
  • Combination products. 297 rows mix one of ours with another drug (fentanyl + bupivacaine, semaglutide + cyanocobalamin, tirzepatide + niacinamide). The other ingredient is not one of our 13, but the recall still counts for ours.
  • One event, many rows. 238 events for 890 rows. The largest event has 103 rows (The Compounding Pharmacy of America). 140 events have just 1.
  • "Ongoing" lasts years. The median Ongoing recall started 459 days ago. The oldest, D-057-2013, started in September 2012. Part 4 below has the full spread.
  • "Completed" has no end date. All 7 Completed rows have termination_date empty. Every Terminated row has one.

How it joins to the others

The chain we try, in order
recall text ──parse──▶ NDC ──RxNorm ndcstatus──▶ RxCUI ──▶ ingredient (Drug)
                          └──NDC Directory──▶ product ──▶ application no. (Product) ──▶ label
recall text ──whole-word ingredient match──▶ ingredient (Drug)          ← fallback, always works

D027 says a recall belongs to a Product (application number), and Products roll up to a Drug (ingredient RxCUI). The table shows how far each step gets, for the 527 rows that have an NDC.

For compounded products the directory route almost never works, and RxNorm's answer is usually ALIEN or "PROPRIETARY". For the active set it is worse: of 116 Ongoing rows, 80 have an NDC, 36 get an RxCUI and 52 get any match (45%).

Who fails everywhere

Top firms: Pharmakon (27 rows), ProRx (14), SCA Pharmaceuticals (9), Apollo Care (8). All 8 Ongoing examples the script lists are Apollo Care semaglutide vials (71170-810-01, 71170-724-04, …). These are the same family as DQ29's 71170-950-25. The labeler (first 5 digits) is known for 20 of the 113.

Text-only fallback

The whole-word match finds the ingredient for all 494 rows that RxNorm's NDC lookup misses. It is how we selected the rows, so it never fails at the Drug level. Going further, to a strength or a clinical drug, does not work from text. We sent the first words of each description to RxNorm's approximate search:

  • Top answer names our ingredient: 386 of 494 (78%).
  • Top answer has the right strength: 96 of 239 that state one (40%). "SEMAGLUTIDE 0.9mg" came back as "semaglutide 9 MG".
  • 175 top answers are retired RxNorm concepts (143 not current, 32 obsolete).
What's messy (measured)
  • NDCs get reused. D-0153-2017 is Hospira fentanyl, NDC 0409-4093-32. Today the NDC Directory has that code on a chromium product. A recall NDC must be matched with its date in mind.
  • 75 of the 193 directory hits are only in the excluded file (discontinued or inactivated products). Using the main file alone would lose 39% of directory matches.
  • 11-digit NDCs written 5-4-2 cannot be turned back into the 10-digit form without a lookup. We compare everything as 11 digits.
Decision to propose
  • Identity order for a recall: NDC → NDC Directory (all four files) for Product, NDC → RxNorm for RxCUI, whole-word text match for the ingredient. Store which route matched.
  • Link a recall to a Drug always, to a Product when found. Do not use text matching to guess a Product or strength.
  • Accept RxNorm ALIEN only when its name confirms the ingredient. Treat "PROPRIETARY" as no match.
  • Rows with no NDC match go on a review list with a compounded tag where it applies. Never drop them.

Over 3 years the pattern holds: 125 new rows in 157 weeks, mean 0.8. Every report_date is a Wednesday.

What's messy (measured)
  • Updates land on old rows. The 4 recent closures (D-0296/0304/0308-2023, D-0385-2025) were reported in 2023 and 2025 and closed in 2026. Their report_date did not move. A load that only takes "new report_date" would never see them close.
  • No row has a "last modified" field. The only way to see a change is to compare this week's file to last week's.
  • Our earlier API pull (485 rows, data of 2026-10-07) vs the bulk file (2026-10-14): 0 rows changed. Changes are rare, which makes each one worth a ChangeEvent.
Decision to propose
  • Weekly full snapshot + diff on recall_number, not an append by report_date. The file is 28 MB; a full reload costs nothing.
  • ChangeEvents from recalls: RecallNew, RecallStatusChanged, RecallClassChanged. Expect about 1 a week for our 13, with bursts of 10+ when one compounder recalls many vials. Group them by event in the feed.

For comparison, the 767 recalls FDA did close took a median of 591 days (75% within 707 days, 90% within 1,046 days). So "Ongoing" mostly means "FDA has not done the paperwork yet". Age alone cannot tell us if the product is still around.

The expiry dates tell us more

The script reads expiry and beyond-use dates out of code_info. It finds one for 65% of all rows. For the 116 Ongoing rows:

Safety officer lens (persona view, not a real interview).

If every lot expired in 2022, it isn't on my shelf. Don't put it in my morning count. But don't hide it either: I may still have patients who received it, and I need it when someone asks.

Tell me the class, how old it is, and whether we could still have it. Show me one line per recall, not ten lines for ten vial sizes.

Rule to propose
  • Active = status Ongoing and (any lot unexpired, or "all lots", or no expiry found). Show class, age and the newest lot expiry.
  • Ongoing · lots expired = Ongoing, every parsed lot expired. Listed under the active list, collapsed. Not in the headline count.
  • Closed = Terminated or Completed. History only.
  • Count and show events, with the product rows inside. Class I sorts first. A new badge marks anything that changed since her last review (D028).

Result today: 116 Ongoing rows → 66 Active rows = 29 recall events; 50 rows move to "lots expired". Active rows by ingredient: semaglutide 31, tirzepatide 12, fentanyl 7, buprenorphine 5, oxycodone 3, hydromorphone 2, morphine 2, and 1 each for methadone, tramadol, liraglutide and exenatide. 2 Active rows are Class I.

Assumption: the expiry parser is a regex, not checked by hand. 3 Active rows are over 3 years old: 2 Akorn "all lots" recalls and 1 Apollo Care row with no expiry. Hand-check these before the demo.
