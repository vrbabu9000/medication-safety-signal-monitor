DailyMed: the label text Part B reads

DailyMed is the National Library of Medicine's home for official US drug labels (SPL, Structured Product Labeling: one XML document per product per company). Part B (the AI step) reads these labels to learn which reactions are already mentioned. This page picks one reference label per ingredient, measures its structure, and counts how often our labels change. Every number was measured on 2026-10-20 by prototypes/explore/label_atlas.py (steps refs, sections, census, dailyzip) against the live DailyMed API, one daily update file and the 2026 Q1 + Q2 FAERS bulk files.

Verdict: KEEP DailyMed stays the label truth (D019). Two rules change: the reference label is picked through the FAERS application number, and a new label version is not a change event until the 4 safety sections actually change. One reference label (methadone) is stale and needs a flag. Companion pages: srlc.html (when a reaction was added) · onsides.html (benchmark).

Overview

One reference label per ingredient

Each ingredient has dozens to hundreds of labels (brand, generics, repackagers). Part B needs one label to compare against. The rule we tested: take the product FAERS names most often as the primary suspect (its application number, nda_num), then take that application owner's own label. If that product is a generic and the brand's label still exists, use the brand label for the same route.

What's messy (measured)

Found on the 13 reference labels
  • Three ways to code a subsection. All 13 use the generic code 42229-5 somewhere. 7 also use the specific codes 90374-0 (clinical trials) and 90375-7 (postmarketing). Ozempic and Byetta repeat the parent code on the child. A filter on child codes would miss parts of every label. Taking everything nested under the 4 parent codes works for all 13.
  • Brand labels that no longer exist. Duragesic: only a 2011 repackager copy remains. Dolophine: only 4 repackager copies, the newest from 2020. Ultram: no label at all. Fentanyl, methadone and tramadol therefore fall back to the most-reported generic label.
  • A stale reference label. The methadone generic (Ascend, v11, Jun 2022) lacks two class-wide opioid additions that SrLC dates to Dec 2023 (hyperalgesia) and Dec 2025 (esophageal dysfunction). The 6 other opioid analgesic references have both. Against this label, both reactions would show as false "unlabeled" signals. (Brixadi lacks "hyperalgesia"; it treats opioid use disorder, not pain, so that may be correct. Unverified.)
  • Version numbers skip and repeat. Trulicity's history lists 39 versions with numbers up to 62. MS Contin (our morphine reference) lists version 16 twice, and the Ozempic tablet label lists version 13 twice.
  • Tables with merged cells. 11 merged cells in Trulicity and in Byetta, 7 in Mounjaro. Flattening a table row by row breaks when a cell spans rows.
  • Deep nesting. Mounjaro's Adverse Reactions goes 6 levels deep and has 19 subsections.
  • Size. The 4 safety sections run from 20,655 characters (Ozempic) to 51,600 (tramadol). The opioid labels are about twice the GLP-1 labels, mostly Warnings & Precautions.
  • FAERS rows with no application number. 2,552 of 22,634 single-ingredient semaglutide primary-suspect rows (11%) have a blank nda_num. Tirzepatide: 1,548 of 42,575 (4%). Those rows need the ingredient-level reference label.

What this means for "what changed since yesterday"

About 1 label version per weekday reaches our 13 ingredients, almost all generics and repackagers. In the same 90 days FDA approved exactly 1 safety change for them. If every new version raised a change event, the officer would see about 100 events in 90 days, and only 1 would be a safety change.

6

Decision

Proposed
  • Reference label: for each FAERS application, its owner's label; for each ingredient, the most-reported application's label (table above). When the brand label is gone, use the generic and show "generic reference" on screen.
  • Freshness check: flag a reference label that is older than the latest SrLC change for that ingredient. Methadone is flagged today. Option to test: pick the most recently updated generic among the top 3 applications instead.
  • Extraction scope: everything nested under 34066-1, 34070-3, 43685-7 (or 34071-1) and 34084-4. Never filter on child codes. Tables are flattened with merged cells expanded.
  • Change detection: a daily job asks the API for each ingredient's labels published that day (13 calls). For reference labels only, it fetches the new XML, hashes each of the 4 sections, and raises a ChangeEvent only when a hash changes. Other versions are logged, not shown.
  • Missed days: only the latest daily file is listed, so recovery uses the weekly file (Mon to Fri) or the API's gte filter plus history.json.
  • Cache key for Part B results: setid + version + publish date + section hash.
